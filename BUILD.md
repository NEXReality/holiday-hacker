# Building & Testing Holiday Hacker Android

This document covers everything from "fresh checkout" to "signed APK on a real
device with a working alarm." Read once, follow phase-by-phase.

## Prerequisites (one-time setup)

1. **Node.js 18+** (already installed: v22 confirmed). `node --version` should print v18 or higher.
2. **Android Studio** (bundles JDK 17 + Android SDK + emulator + Gradle).
   Download: https://developer.android.com/studio
3. After installing Android Studio, open it once and accept license dialogs so
   the SDK auto-installs. SDK platforms 34 and 35 are needed.
4. **An Android device or emulator** for testing. A real device with USB
   debugging is strongly recommended for alarm verification (emulators have
   limited Doze / DND simulation).

No global npm installs are required — Capacitor lives in `node_modules/`.

## Project layout

- `index.html`, `app.js`, `styles.css`, `trips/`, `plan/`, `calendar/`,
  `holidays/`, `profile/`, `database/` — the existing web app, source of truth.
- `sync-www.js` — copies the above into `www/` (Capacitor `webDir`).
- `www/` — generated. Don't edit by hand. Re-created by `npm run sync:www`.
- `capacitor.config.json` — appId / appName / webDir.
- `android/` — generated by Capacitor. Inside it:
  - `app/src/main/AndroidManifest.xml` — permissions and components.
  - `app/src/main/java/in/holidayhacker/app/` — Java alarm plugin sources.
  - `app/src/main/res/` — icons, splash, strings, colors, layouts.

## Build cycle (every time you change HTML/CSS/JS)

```powershell
npm run sync:www       # rebuilds www/
npx cap sync android   # mirrors www/ into android/app/src/main/assets/public
```

There's also a one-shot:

```powershell
npm run android:open   # sync + open Android Studio
```

## Phase 1 — First debug APK

1. Run `npm run android:open` from the project root. Android Studio launches
   pointing at `android/`.
2. Wait for Gradle sync to finish (status bar at the bottom).
3. Connect an Android device with USB debugging enabled, **or** start an
   emulator from Tools -> Device Manager.
4. Click the green Run button (Shift+F10). The APK installs and launches.
5. **Verify the wrap**: navigate Home -> Plan -> Calendar -> Trips. JSON data
   should load (state-city, holidays, destinations) — proves the bundled
   `database/` is being served from the WebView's `https://localhost` origin.

Expected: the existing site runs identically inside the app, no internet
required for data.

## Phase 2 — Verify the alarm plugin

This is the critical test. Do NOT skip.

### 2a. One-tap test from inside the app (recommended)

The Profile page now has a **Reminder Test** card that only appears when the
HolidayAlarm plugin is detected (i.e. running inside the Android wrapper, not
the plain web build).

1. Open the app on the phone, go to Profile (bottom nav).
2. Scroll to the **Reminder Test** card just above "Clear Data".
3. Tap **Ring test alarm in 30 seconds**. The first time, Android will prompt
   for "Allow notifications" and may open an "Allow exact alarms" settings
   page — grant both.
4. Lock the phone. Turn Do Not Disturb ON. Wait ~30 seconds.
5. **Expected**: screen wakes, full-screen Holiday Hacker alarm appears over
   the lock screen with "Dismiss" and "Snooze 10 min" buttons, alarm tone
   loops on `STREAM_ALARM`, vibration. Dismiss stops everything.
6. To abort an unfired test, press **Cancel pending test alarm** on the same
   card.

### 2b. DevTools fallback

If you want to schedule programmatically (e.g. test 5 minutes ahead, or test
multiple alarms):

1. With the app running on the device, open Chrome on a desktop and go to
   `chrome://inspect/#devices`. The WebView is listed.
2. Click "inspect" -> opens devtools attached to the WebView.
3. In the console:

   ```js
   await Capacitor.Plugins.HolidayAlarm.requestPermissions();
   await Capacitor.Plugins.HolidayAlarm.schedule({
     id: 'test-1',
     timestamp: Date.now() + 60000,
     title: 'Test alarm',
     body: 'Should ring full-screen with sound'
   });
   // List currently scheduled alarms
   await Capacitor.Plugins.HolidayAlarm.listScheduled();
   // Cancel a specific one
   await Capacitor.Plugins.HolidayAlarm.cancel({ id: 'test-1' });
   ```

### 2c. Reboot persistence

1. Schedule another test alarm 5 minutes in the future.
2. Reboot the phone. Wait for it to fully boot.
3. Wait the remaining time.
4. **Expected**: the alarm still fires.

The `BootReceiver` re-arms persisted alarms from device-protected storage.

### 2d. Real-flow test via the trips UI

1. From the app, plan a trip and confirm it.
2. On the Trips card, ensure the "Reminders" toggle is ON. The card now shows
   the actual computed date next to "30 days before • " — verify this date is
   what you expect.
3. To exercise the leave alarm, set "Days before trip" so the resulting date
   is in the very near future (or temporarily edit `holidayHacker_confirmedTrips`
   in DevTools localStorage so the trip's `windowStart` is e.g. tomorrow, then
   set days before = N where the firing moment is ~1 min from now).
4. **Expected**: when the moment arrives, the alarm rings exactly as in 2a.

### 2e. Cancellation

1. With an alarm scheduled, toggle "Reminders" OFF on the trip card. Wait
   past the original fire time.
2. **Expected**: no alarm fires.

If all four checks pass, the alarm system works.

## Phase 3 — Building a release AAB for Play Store

### 3a. Generate a signing keystore (one-time)

```powershell
keytool -genkey -v -keystore holiday-hacker.keystore -alias holidayhacker -keyalg RSA -keysize 2048 -validity 10000
```

Store the `.keystore` file securely. You will need this to sign every release.
**Lose it and you can never update your Play Store listing.**

### 3b. Configure Gradle to sign release builds

In `android/app/build.gradle`, inside the `android { }` block, add:

```gradle
signingConfigs {
    release {
        storeFile file("../holiday-hacker.keystore")
        storePassword System.getenv("HH_KEYSTORE_PWD")
        keyAlias "holidayhacker"
        keyPassword System.getenv("HH_KEY_PWD")
    }
}
buildTypes {
    release {
        minifyEnabled false
        signingConfig signingConfigs.release
    }
}
```

(If you set `HH_KEYSTORE_PWD` and `HH_KEY_PWD` as environment variables before
launching Android Studio, signing happens automatically.)

### 3c. Build signed AAB

In Android Studio: **Build -> Generate Signed Bundle / APK -> Android App
Bundle -> Next -> select keystore -> next -> release**.

Output: `android/app/release/app-release.aab`

This is the file you upload to Play Console.

## Phase 4 — Permission grant rates and OEM quirks

Some Android OEMs aggressively kill background apps. The plugin tries to
help, but the user may need to do these once:

- **Xiaomi / Redmi / POCO**: Settings -> Apps -> Holiday Hacker -> Battery
  saver -> No restrictions. Also enable Autostart.
- **OPPO / Realme**: Settings -> Battery -> App Battery Management -> Holiday
  Hacker -> Allow background activity.
- **Vivo / iQOO**: Settings -> Battery -> Background Power Consumption ->
  Holiday Hacker -> Allow background activity.
- **Huawei / Honor**: Settings -> Apps -> Holiday Hacker -> Battery -> App
  launch -> Manage manually -> all toggles ON.
- **OnePlus**: Settings -> Battery -> Battery optimization -> Holiday Hacker
  -> Don't optimize.
- **Samsung**: Settings -> Apps -> Holiday Hacker -> Battery -> Unrestricted.

The first time the user toggles a reminder, `requestAlarmPermissionsOnce()`
in `trips/trips.js` shows a one-time confirm dialog on these OEMs offering
to open battery settings.

## Target SDK

The project targets **API 35 (Android 15)** with `minSdkVersion = 23`
(Marshmallow 6.0+). See `android/variables.gradle`. This satisfies Google
Play's "new apps must target API 35" requirement that took effect in
late 2025 and covers ~99.9% of active Android devices in the wild.

Bumping minSdk to 23 was deliberate — the runtime-permissions model
(POST_NOTIFICATIONS, SCHEDULE_EXACT_ALARM) requires API 23+. The alarm
plugin's permission flow assumes this baseline.

## Sanity checklist before publishing

- [ ] Manifest declares all alarm permissions (verified — see `AndroidManifest.xml`).
- [ ] `MainActivity.java` calls `registerPlugin(HolidayAlarmPlugin.class)`.
- [ ] Reboot test passes.
- [ ] DND test passes (alarm still rings on `STREAM_ALARM`).
- [ ] Trip create -> reminder edit -> alarm fires at correct moment.
- [ ] Trip remove -> alarm cancelled (verify via `Capacitor.Plugins.HolidayAlarm.listScheduled()` in devtools).
- [ ] APK size sanity: ~5–8 MB expected.
- [ ] Privacy policy URL is live and matches Play Console submission.
- [ ] Store listing mentions "alarm/calendar core functionality" to justify
      `SCHEDULE_EXACT_ALARM` and `USE_FULL_SCREEN_INTENT`.

## Updating the app later

For HTML/CSS/JS-only changes:

1. Edit files at the project root.
2. `npm run android:copy`
3. Bump `versionCode` and `versionName` in `android/app/build.gradle`.
4. Generate signed AAB.
5. Upload to Play Console -> Production -> review (~24 hours for updates).

For native plugin changes:

1. Edit Java files in `android/app/src/main/java/in/holidayhacker/app/`.
2. Same as above plus a clean Gradle build.
